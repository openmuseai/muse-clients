# OpenMuse Workbench 高保真规格

状态：实施中（2026-09-23）

## 1. 目标与方法

本规格将旧版桌面产品当作运行中的黑盒，只记录用户可观察到的信息架构、交互状态、尺寸和响应结果，再以 OpenMuse 自有代码、设计令牌、图标和文案重新实现。目标是保留成熟桌面工作台的使用习惯，不复制旧仓库源码、主题文件、图标、插画、字体文件或品牌资源。

“高保真”在这里指结构、密度、状态反馈和操作路径接近，不表示像素级复制受保护的品牌表达。任何来自第三方的代码或资源必须先有可追溯来源、兼容许可证和 notices；改名不能消除原许可证义务。

## 2. 产品信息架构

```text
OpenMuse Host
├── Local Workspace（左侧）
│   ├── 搜索
│   ├── 新建本地文档
│   ├── 本地资源树/列表
│   ├── 插件入口
│   └── 回收站（待实现）
├── Editor Surface（中心）
│   ├── 资源标题与收藏
│   ├── 插件编辑器/Viewer
│   └── 无资源欢迎态
└── Assistant Surface（右侧，可折叠）
    └── DSH Agent 插件
```

Host 只拥有窗口、Workspace/Resource 状态、布局、命令路由和插件槽位。Helix、文件 Viewer、DSH 以及未来 Markdown/Office 编辑器都必须通过插件契约提供，不得把其页面或运行时重新写回 Host。

## 5. 设置边界

允许出现的设置分类只有：Workspace（内含 Appearance）、插件、Agent、快捷键、隐私/诊断和关于。首发版本不得出现账号、登录、组织、成员、云同步、在线协作、分享、计费、云 AI 或旧产品品牌入口。

DSH 的模型配置属于 DSH 插件。Host 只提供凭据句柄、受限 Workspace capability 和审计事件，不读取或记录明文密钥。

## 6. Clean-room 与发布检查

每次 UI 合并必须同时满足：

1. 变更只引用本仓库自有实现或已批准的许可证兼容依赖。
2. Host 生产依赖仍只面向插件 SDK 与 distribution，不直接依赖具体插件包。
3. 搜索、新建、资源切换、面板折叠和设置分类有 widget 测试。
4. macOS/Windows 分别完成 golden、键盘、中文 IME、屏幕阅读器、100%–200% 缩放和安装包真机验证。
5. 发布前由律师复核产品视觉、商标、第三方许可证、SBOM 和 notices；技术隔离不是法律意见。
